# Agent instructions

- Feature and reference documentation describes the current supported API and behavior. Do not narrate development history, abandoned designs, or unreleased intermediate implementations, or present unchanged behavior as compatibility reassurance.
- Upgrade guides compare actual released behavior with the target release. Do not describe unreleased APIs as previously supported APIs.
- Keep library documentation independent of consuming applications. Clearly introduce application-specific examples and terminology.
- Forms own values, validation, payload transformations, and baselines. Saving and transport orchestration belong to the caller.
- Temporary form drafts are unversioned. Do not introduce schema versions, migration layers, or implicit metadata backfills.
